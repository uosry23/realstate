# العقار

نظام عربي باتجاه RTL لإدارة عمليات شركات التطوير والتسويق العقاري. يدعم إدارة المشاريع والوحدات والعملاء المحتملين والوسطاء وطلبات ما بعد البيع والصيانة.

## المتطلبات والإعداد

1. استخدم Node.js المتوافق مع Next.js 16، ثم ثبّت الحزم باستخدام `npm install`.
2. انسخ `.env.example` إلى `.env.local` وأدخل عنوان مشروع Supabase ومفتاحه القابل للنشر (`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`)، واضبط `NEXT_PUBLIC_APP_URL` على عنوان التطبيق. يدعم التطبيق مؤقتًا `NEXT_PUBLIC_SUPABASE_ANON_KEY` للتوافق مع الإعدادات القديمة. لا تضع مفتاح `service_role` في متغيرات `NEXT_PUBLIC_` أو في الواجهة.
3. نفّذ ملفات `supabase/migrations` بالترتيب في مشروع Supabase. الهجرة الثانية تنشئ الشركة وملف المدير عند التسجيل الأول، والهجرة الخامسة تضيف الأدوار ودعوات الأعضاء وسياسات RLS.
4. أضف عنوان التطبيق المحلي وعناوين النشر إلى قائمة Redirect URLs في إعدادات Supabase Auth. اضبط قالب Confirm signup ليستخدم `{{ .RedirectTo }}?token_hash={{ .TokenHash }}&type=email`، وقالب Reset password ليستخدم `{{ .RedirectTo }}&token_hash={{ .TokenHash }}&type=recovery`؛ التطبيق يمرر `next=/reset-password` ضمن رابط الاستعادة. تتطلب رسائل البريد إعداد SMTP صالحًا.
5. شغّل التطبيق باستخدام `npm run dev` وافتح `http://localhost:3000`.

## الوظائف الحالية

- تسجيل الدخول وإنشاء حساب مستخدم وشركة، مع جلسات آمنة عبر Cookies في Next.js، وتأكيد البريد واستعادة كلمة المرور.
- الأدوار: المدير يدير الأعضاء والدعوات ويملك صلاحيات التشغيل؛ الموظف يضيف ويعدّل سجلات التشغيل؛ المشاهدة فقط يقرأ.
- ينشئ المدير رمز دعوة أحادي الاستخدام مرتبطًا ببريد محدد وصالحًا 7 أيام، ثم يشاركه مع العضو عبر قناة آمنة. يُدخل العضو الرمز والبريد نفسه أثناء التسجيل، وتُحفظ تجزئة الرمز فقط في قاعدة البيانات.
- سياسات RLS تعزل سجلات كل شركة، وتطبق الأدوار على كل عمليات الكتابة. حماية الخادم في Server Actions مفعلة أيضًا.
- إنشاء المشاريع والوحدات والعملاء والوسطاء وطلبات الخدمة.
- تعديل بيانات المشاريع والوحدات والعملاء والوسطاء وطلبات الخدمة، مع إعادة توزيع العملاء وتفعيل الوسطاء أو إيقافهم.
- سجل متابعة للعميل بمواعيد وملاحظات وإمكانية تسجيل اكتمال المتابعة.
- بحث وتصفية حسب الحالة والاسم أو الكود في قوائم التشغيل.
- ترقيم صفحات لقوائم التشغيل، مع بقاء التصفية عند الانتقال بين الصفحات.
- صفحات تفاصيل للعملاء والوحدات، مع عرض سجل متابعة العميل وتاريخ تغييرات حالة الوحدة.
- تحديث مراحل العملاء وحالات الوحدات وطلبات الخدمة. تغييرات الوحدات تحفظ في سجل الحالة الموجود بقاعدة البيانات، ويتطلب تحويل الوحدة إلى مباعة تأكيدًا.
- لوحة تشغيل تعرض ملخصًا للمشاريع والوحدات والعملاء وطلبات الخدمة.

الهجرة الرابعة تضيف قيودًا لمنع إنشاء ارتباطات جديدة بين سجلات شركات مختلفة. بعد التأكد من تناسق أي بيانات قديمة، يمكن التحقق من القيود باستخدام `VALIDATE CONSTRAINT` على القيود التي أضافتها الهجرة.

## الفحوص

- `npm run lint`
- `npx tsc --noEmit`
- `npm run build`

اختبارات سياسات الأدوار في `supabase/tests/company_roles_rls.test.sql`، وتشغّل محليًا باستخدام `supabase test db` بعد تثبيت Supabase CLI وDocker.
