# تقرير التقدم في مشروع CRM العقاري

آخر تحديث: 2 نوفمبر 2026 — مرتبط بمشروع Supabase `RealState`.

## ملخص المشروع

المشروع تطبيق CRM عربي باتجاه RTL لإدارة عمليات شركات التطوير والتسويق العقاري. بنيته الحالية تستخدم Next.js App Router وTypeScript وTailwind CSS وSupabase. يغطي التطبيق المشاريع والوحدات والعملاء المحتملين ومتابعاتهم والوسطاء وطلبات ما بعد البيع والصيانة.

## ما تم تنفيذه

### الدخول والعضوية

- تسجيل الدخول وإنشاء حساب الشركة، مع عميل Supabase منفصل للخادم والمتصفح وجلسات مبنية على Cookies.
- تأكيد البريد الإلكتروني واستعادة كلمة المرور وتغييرها، مع التحقق من وجهة إعادة التوجيه.
- إضافة أدوار الشركة: مدير، موظف، ومشاهدة فقط.
- صفحة `/team` للمدير لإدارة أدوار الأعضاء وإنشاء الدعوات وإلغائها.
- الدعوة مرتبطة ببريد إلكتروني، صالحة 7 أيام وتستخدم مرة واحدة. يُنشأ الرمز عشوائيًا وتُحفظ تجزئته، ويُمرر الرمز عند التسجيل ثم يُزال من بيانات المستخدم الوصفية.
- منع خفض دور المدير الأخير أو حذفه على مستوى قاعدة البيانات.

### مجالات التشغيل

- إنشاء وتعديل المشاريع.
- إنشاء وتعديل الوحدات، وتسجيل حالاتها: متاحة، محجوزة، ومباعة.
- منع الكتابة فوق تغيير حالة أحدث باستخدام الحالة المتوقعة في التحديث، وتسجيل تاريخ تغييرات الوحدة وفاعل التغيير عبر مشغل قاعدة البيانات.
- إنشاء وتعديل العملاء المحتملين، توزيعهم على الوسطاء والمشاريع، وتحديث مرحلة العميل.
- سجل متابعة العملاء بملاحظات ومواعيد وإمكانية تسجيل إتمام المتابعة.
- إنشاء وتعديل الوسطاء وتفعيلهم أو إيقافهم.
- إنشاء وتعديل طلبات ما بعد البيع والصيانة وتحديث حالتها.
- لوحة تشغيل بإجماليات المشاريع والوحدات والعملاء والوسطاء وطلبات الخدمة.
- البحث والتصفية وترقيم الصفحات في قوائم التشغيل، مع الحفاظ على المرشحات عند التنقل بين الصفحات.
- صفحات تفاصيل للوحدات والعملاء المحتملين.

### الصلاحيات وعزل البيانات

- المدير والموظف يستطيعان إنشاء وتعديل سجلات التشغيل؛ المشاهد يستطيع القراءة فقط.
- إدارة الأعضاء والدعوات متاحة للمدير فقط.
- تُخفى أدوات الكتابة في الواجهة عن المشاهد، وتتحقق Server Actions من الدور قبل الكتابة.
- سياسات RLS تعزل بيانات الشركات وتطبق أدوار الكتابة على جداول المشاريع والوحدات والعملاء والوسطاء وطلبات الخدمة والمتابعات.
- إجراءات الكتابة تضيف نطاق الشركة، وتتحقق من علاقات مثل المشروع أو الوسيط أو الوحدة. أضيفت قيود علاقات مركبة لمنع ربط سجلات من شركات مختلفة.
- لا يستخدم عميل الخادم مفتاح `service_role`؛ إعدادات البيئة النموذجية تحتوي أسماء المتغيرات دون أسرار.

## أهم الملفات

- `src/app/`: صفحات لوحة التشغيل والمشاريع والوحدات والعملاء والوسطاء وطلبات الخدمة والفريق والمصادقة.
- `src/features/*/actions.ts`: إجراءات الكتابة والتحقق من العضوية والمدخلات لكل مجال.
- `src/features/*/services/`: استعلامات Supabase المنفصلة حسب المجال.
- `src/lib/supabase/server.ts` و`src/lib/supabase/browser.ts`: عملاء Supabase للخادم والمتصفح.
- `src/lib/auth/`: جلب عضوية المستخدم وتحديد صلاحية الكتابة.
- `supabase/migrations/0001` إلى `0005`: مخطط البيانات، تهيئة الشركة، المتابعات، قيود العلاقات، والأدوار والدعوات وسياسات RLS.
- `supabase/tests/company_roles_rls.test.sql`: اختبارات pgTAP أولية للأدوار وعزل الشركات.
- `docs/data-model.md`: الجداول والأدوار وفصل البيانات وحالات العمل.
- `README.md`: إعداد المشروع وتشغيله وفحوصه.

## التحقق المنفذ ونتائجه

- `npm run lint`: نجح.
- `npx tsc --noEmit`: نجح.
- `npm run build`: اكتمل بنجاح بعد تشغيله خارج قيد العزل الذي كان يمنع إنشاء عملية فرعية (`spawn EPERM`).
- تطبيق الهجرات السبع على مشروع Supabase `RealState` الفعلي، مع تفعيل RLS للجداول العشرة وتسجيل الهجرات في قاعدة البيانات.
- فحص Data API بالمفتاح القابل للنشر: نجح برد HTTP 200.
- اختبار RLS فعلي داخل معاملة متراجعة: أثبت دور المدير والموظف والمشاهد، عزل شركات متعددة، ومنع المشاهد من الكتابة أو تغيير الأدوار. لم يترك الاختبار أي بيانات.
- مستشار الأمان في Supabase: بلا تحذيرات بعد نقل دوال RLS المساعدة إلى مخطط `private` وإغلاق تنفيذ دوال المشغلات عبر الـAPI.
- فحص التطبيق محليًا: صفحة الدخول أعادت 200 بلا رسالة نقص الإعداد، والمسار المحمي `/projects` أعاد 307 إلى `/login` عند عدم وجود جلسة.

## ما لم يُتحقق منه أو بقي لإكماله

1. يلزم ضبط Redirect URLs وقوالب البريد وSMTP في Supabase قبل اختبار التسجيل وتأكيد البريد واستعادة كلمة المرور من المتصفح.
2. اختبارات pgTAP الموجودة لم تُشغّل لأن أدوات Supabase CLI وDocker و`psql` غير متاحة هنا. اختبار RLS المباشر المنفذ يغطي المدير والموظف والمشاهد وعزل الشركات، لكنه لا يحل محل مجموعة pgTAP الكاملة.
3. لا توجد حاليًا واجهات حذف لسجلات التشغيل؛ السلوك القائم هو الإنشاء والتعديل وتغيير الحالة. لا توجد عمليات محاسبة أو فواتير أو مدفوعات ضمن نطاق المشروع.

## الحالة الحالية

الواجهة الأساسية، تدفقات الإنشاء والتعديل، إدارة الأدوار، وربط الخادم بـSupabase مطبقة ومتصلة فعليًا. فحوص TypeScript وESLint والبناء ناجحة، وكذلك فحص RLS المباشر. تبقى تهيئة بريد Supabase وتجربة التسجيل الحقيقية من المتصفح قبل الإطلاق.
