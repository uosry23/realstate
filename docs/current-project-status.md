# حالة مشروع «العقار» الحالية

آخر تحديث: 7 نوفمبر 2026.

## المنفذ والمتحقق منه

- CRM عربي RTL مربوط بمشروع Supabase `RealState`.
- الأدوار: مدير، موظف، مشاهدة فقط، مع RLS لعزل بيانات الشركات.
- لوحة الموظفين تعمل على `/dashboard` وتشمل المشاريع والوحدات والعملاء والوسطاء وطلبات الخدمة والفريق.
- تم اختبار الدخول بحساب المدير بنجاح؛ زر **دخول فريق العمل** ينقل المستخدم المسجل إلى `/dashboard`.
- أُنشئت بيانات اختبار فعلية داخل شركة المدير:
  - مشروع: **كمبوند جرين فالي** — القاهرة الجديدة.
  - مشروع: **أبراج النخبة** — العاصمة الإدارية.
  - وحدة متاحة: **A-101** في أبراج النخبة، شقة، الدور الأول، 145 م².
- الصفحة الرئيسية `/` أصبحت واجهة زائر عامة، وصفحة تفاصيل عامة للوحدة على `/properties/[id]`، مع نموذج طلب معاينة يُفترض أن ينشئ Lead.
- فحوص `npm run lint` و`npx tsc --noEmit` ناجحة.

## العطل الحالي

واجهة الزائر لا تعرض الوحدة رغم وجودها في قاعدة البيانات.

**السبب المؤكد:** الاستعلام يطلب العرض `public.available_unit_listings`، لكن العرض غير موجود في مشروع Supabase الحالي. تم التحقق مباشرة من Data API، وكانت الاستجابة:

```text
PGRST205: Could not find the table 'public.available_unit_listings' in the schema cache
```

لذلك تظهر رسالة «تعذر تحميل الوحدات المتاحة» بدل الكروت. البيانات التشغيلية نفسها سليمة؛ لوحة المدير تُظهر مشروعين ووحدة متاحة.

## المطلوب لإصلاحه

1. تطبيق migration [0010_public_property_listings.sql](../supabase/migrations/0010_public_property_listings.sql) على مشروع Supabase `RealState`.
2. تتحقق الـmigration من إنشاء:
   - عرض عام للوحدات المتاحة فقط.
   - دالة آمنة لتسجيل اهتمام الزائر وتحويله إلى Lead للشركة الصحيحة.
3. بعد التطبيق، إعادة اختبار `/` وفتح صفحة الوحدة وإرسال طلب معاينة.
4. رفع تغييرات الكود وmigration إلى GitHub ثم نشرها عبر Vercel حتى تصل للإنتاج.

## ملاحظة وصول Supabase

محاولة فتح لوحة Supabase في هذه الجلسة وصلت لصفحة تسجيل الدخول، لذلك لم يمكن تطبيق migration من الواجهة تلقائيًا. يلزم تسجيل الدخول إلى حساب Supabase الذي يملك المشروع أو إعادة ربط موصل Supabase، ثم يمكن تطبيقها فورًا.
