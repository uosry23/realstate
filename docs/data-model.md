# نموذج بيانات CRM العقاري

النطاق الحالي تشغيلي وإداري: مشاريع، وحدات، عملاء محتملون، وسطاء، وطلبات ما بعد البيع والصيانة. لا يشمل محاسبة أو فواتير أو مدفوعات.

## الجداول

- `companies`: الشركة المالكة للبيانات.
- `profiles`: ربط مستخدم المصادقة (`auth.users`) بشركة واحدة.
- `company_invitations`: دعوات أعضاء الشركة، مع الدور والبريد وتاريخ الانتهاء وحالة القبول أو الإلغاء. تخزن قاعدة البيانات تجزئة الرمز فقط.
- `projects`: المشاريع العقارية داخل الشركة.
- `units`: الوحدات داخل مشروع، بحالات `available` و`reserved` و`sold`.
- `unit_status_events`: سجل تغيير حالة الوحدة مع المستخدم والوقت.
- `brokers`: الوسطاء داخل الشركة.
- `leads`: العملاء المحتملون ومراحل المتابعة.
- `lead_follow_ups`: ملاحظات المتابعة ومواعيدها وحالة إتمامها، مرتبطة بالعميل والشركة والمنشئ.
- `service_requests`: طلبات ما بعد البيع وشكاوى الصيانة.

## الأدوار

- `manager`: يدير الأعضاء والدعوات، ويقرأ ويضيف ويعدّل سجلات التشغيل.
- `employee`: يقرأ ويضيف ويعدّل سجلات التشغيل، ولا يدير أعضاء الشركة.
- `viewer`: يقرأ سجلات الشركة فقط.

تُفرض الأدوار في Server Actions وسياسات RLS، وليس في الواجهة وحدها. يجب أن يبقى لكل شركة مدير واحد على الأقل. رمز الدعوة أحادي الاستخدام، مرتبط ببريد محدد، وصالح سبعة أيام.

## فصل البيانات

كل سجل تشغيلي يحمل `company_id`. سياسات RLS تسمح للمستخدم المصادق عليه بالوصول إلى صفوف شركته فقط عبر `current_company_id()`، وتحدد صلاحية الكتابة باستخدام `current_company_role()`. العلاقات المركبة تمنع ربط سجلات من شركتين مختلفتين.

## حالات العمل

- الوحدة: متاحة، محجوزة، مباعة.
- العميل المحتمل: جديد، متابعة، معاينة، تفاوض، تم البيع، خاسر.
- طلب الخدمة: مفتوح، قيد التنفيذ، محلول، مغلق.
- نوع الطلب: ما بعد البيع، صيانة.
