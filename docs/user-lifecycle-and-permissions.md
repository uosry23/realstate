# دورة المستخدم والصلاحيات — العقار

هذا المستند يشرح رحلة المستخدم من إنشاء الحساب حتى استخدام نظام CRM، وما يراه وما يستطيع عمله وفق دوره داخل الشركة.

## أنواع المستخدمين

يوجد ثلاثة أدوار داخل كل شركة. لا يمكن للمستخدم رؤية أو الوصول إلى بيانات شركة أخرى.

| الدور | الاسم داخل النظام | الهدف |
| --- | --- | --- |
| `manager` | مدير | إدارة الشركة والفريق وكل بيانات التشغيل. |
| `employee` | موظف | تشغيل بيانات CRM اليومية دون إدارة حسابات الفريق. |
| `viewer` | مشاهدة فقط | متابعة البيانات والتقارير دون أي تعديل. |

## دورة المستخدم

```text
إنشاء شركة أو قبول دعوة
        ↓
إنشاء/تأكيد حساب Supabase
        ↓
تحديد الشركة والدور في الملف الشخصي
        ↓
تسجيل الدخول
        ↓
الانتقال إلى لوحة التحكم حسب الصلاحية
        ↓
استخدام بيانات الشركة فقط
        ↓
تسجيل الخروج أو تغيير كلمة المرور عند الحاجة
```

### 1. إنشاء الحساب والشركة

- من ينشئ حساب شركة جديد يصبح **مديرًا** لها تلقائيًا.
- تُنشأ الشركة وملف المستخدم والعضوية المرتبطة بها عند إكمال التسجيل.
- بعد تأكيد البريد (إن كان مفعّلًا في إعدادات Supabase) يستطيع المستخدم تسجيل الدخول.
- لا يملك الحساب شركة ثانية تلقائيًا؛ البيانات مرتبطة بشركة واحدة في النسخة الحالية من النظام.

### 2. دعوة عضو جديد

- المدير يفتح صفحة **الفريق** وينشئ دعوة باستخدام بريد العضو والدور المطلوب.
- النظام ينشئ رابط دعوة صالحًا لمدة 7 أيام ولمرة استخدام واحدة.
- يسجل المدعو حسابًا بالبريد نفسه، أو يدخل إلى حسابه الموجود، ثم تُربط عضويته بالشركة والدور المحدد في الدعوة.
- يستطيع المدير إلغاء دعوة لم تُستخدم بعد.

### 3. تسجيل الدخول والجلسة

- يسجل المستخدم بريده وكلمة مروره في صفحة الدخول.
- ينشئ Supabase جلسة آمنة عبر Cookies.
- عند فتح أي صفحة محمية، يتحقق الخادم من الجلسة والعضوية والدور قبل إرجاع البيانات.
- المستخدم غير المسجل دخوله يُحوَّل إلى صفحة الدخول.

### 4. استخدام النظام

- تظهر لوحة التحكم والإحصاءات لكل الأدوار، لكن وفق بيانات شركتهم فقط.
- المدير والموظف يمكنهما تنفيذ عمليات التشغيل اليومية.
- مستخدم المشاهدة فقط يرى القوائم والتفاصيل دون أزرار الإنشاء أو التعديل.

### 5. تغيير الدور أو إيقاف الوصول

- المدير وحده يغير دور أعضاء فريقه من صفحة الفريق.
- لا يمكن حذف المدير الأخير أو خفض صلاحياته؛ يجب أن يبقى مدير واحد على الأقل للشركة.
- إلغاء الدعوة يمنع استخدامها، أما العضو الذي انضم بالفعل فيُدار دوره من صفحة الفريق.

## ما يراه كل دور

جميع الأدوار ترى فقط نطاق الشركة التابع لها:

- لوحة التحكم والإحصاءات.
- المشاريع والوحدات وحالاتها.
- العملاء المحتملون وسجل المتابعات.
- الوسطاء.
- طلبات ما بعد البيع والصيانة.

صفحة **الفريق** وإدارة الدعوات تظهر للمدير فقط. لا تظهر لمستخدم المشاهدة أدوات الكتابة أو تعديل الحالة.

| إنشاء/تعديل الوحدات | ✓ | ✓ | — |

`—` تعني أن المستخدم لا يملك هذه الصلاحية.

## حماية الصلاحيات والبيانات

- إخفاء الزر من الواجهة ليس الحماية الوحيدة: كل عملية كتابة تتحقق من الدور على الخادم.
- Row Level Security في Supabase تمنع الوصول إلى صفوف شركة أخرى حتى عند محاولة استدعاء قاعدة البيانات مباشرة.
- المدير والموظف فقط يملكان حق الكتابة إلى بيانات CRM التشغيلية.
- سجل حالة الوحدة يحتفظ بمن نفّذ التغيير وتوقيته، لحفظ التاريخ التشغيلي.
- لا يضم النظام حاليًا صلاحيات للحذف في واجهات التشغيل؛ نطاقه الحالي الإنشاء والتعديل وتغيير الحالة.

## حالات السجلات الظاهرة للمستخدم

- **الوحدة:** متاحة، محجوزة، مباعة.
- **العميل المحتمل:** جديد، متابعة، معاينة، تفاوض، تم البيع، خاسر.
- **طلب الخدمة:** مفتوح، قيد التنفيذ، محلول، مغلق.
- **نوع طلب الخدمة:** ما بعد البيع أو صيانة.
